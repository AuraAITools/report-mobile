## Prerequisites (one-time, machine-level)

```bash
# Node — version is pinned in .nvmrc
nvm use                          # picks up 24.15.0 from .nvmrc

# Ruby — needed for CocoaPods. Use rbenv, not system Ruby.
brew install rbenv ruby-build
echo 'eval "$(rbenv init - zsh)"' >> ~/.zshrc && source ~/.zshrc
rbenv install 3.3.6
rbenv global 3.3.6

# CocoaPods (gem-installed, NOT brew — gives us per-project pinning via Bundler)
gem install cocoapods bundler
rbenv rehash

# Watchman (optional but recommended for Metro)
brew install watchman

# iOS: Xcode + command-line tools
xcode-select --install

# Android: Android Studio with JDK 17; set ANDROID_HOME
```

## Initial setup

```bash
cd report-mobile
nvm use
npm install --legacy-peer-deps          # --legacy-peer-deps required (older transitive deps)

# Regenerate native projects from app.json + plugins
npx expo prebuild --clean

# Install pods (run from project root — Bundler finds the root Gemfile)
(cd ios && bundle exec pod install --repo-update)
```

## Day-to-day dev

Once the dev client is installed on a simulator/device, JS-only changes don't need a rebuild — just Metro:

```bash
npx expo start --dev-client            # start Metro, open dev client to connect
```

### First time on a fresh simulator (or after a native change)

```bash
npx expo run:ios                       # builds + installs dev client + starts Metro
# or
npx expo run:android
```

### When to do a native rebuild

Rebuild via `expo run:ios` / `expo run:android` when:
- You add or change a config plugin in `app.json`
- You add/remove a native dependency (anything with iOS/Android code)
- You upgrade Expo SDK or React Native
- You change `app.json` fields that affect native config (`bundleIdentifier`, splash, icons, permissions, entitlements)

Pure JS/TS/CSS edits never need a native rebuild — Metro hot-reloads.

### Useful Metro/dev-client commands

```bash
npx expo start --dev-client --clear    # clear Metro cache (after upgrades, weird resolver errors)
npx expo start --dev-client --tunnel   # ngrok tunnel for testing on a real device on another network
```

### Re-running pods (after a config plugin or native dep change)

```bash
(cd ios && bundle exec pod install)
```

If pods get really stuck:

```bash
rm -rf ios/Pods ios/build ios/Podfile.lock
(cd ios && bundle exec pod install --repo-update)
```

### Codegen (GraphQL)

```bash
npm run codegen                        # one-off
npm run codegen:watch                  # watch mode
```

## Troubleshooting (nuke-and-reset)

When something is weird and reproducible, this clears every cache:

```bash
rm -rf node_modules ios/Pods ios/build android/build android/.gradle .expo
npm install --legacy-peer-deps
(cd ios && bundle exec pod install --repo-update)
npx expo start --dev-client --clear
```

Watchman occasionally needs its own reset:

```bash
watchman watch-del-all
```

## Notes

- `--legacy-peer-deps` is currently required because some transitive deps (e.g. `react-native-elements`) haven't bumped peer ranges for React 19. Drop the flag once those are replaced or updated.
- The `ios/` and `android/` directories are regenerated by `expo prebuild`. Don't hand-edit them — express native config through `app.json` plugins or `app.config.ts` instead, so it survives a `prebuild --clean`.
